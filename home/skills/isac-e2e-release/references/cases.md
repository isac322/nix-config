### CASE-20261011-release-gated-on-baseline-diff
- 상태: applied
- 출처: omp session 01a12b05 msg 6f2e7e32
- 상황: 사용자가 기준 브랜치의 전체 기능을 e2e로 검증한 뒤 문제가 없을 때만 다음 버전을 정해 끝까지 릴리스하라고 했다. regression이나 신규 버그가 나오면 릴리스하지 말고 보고하라고 했고, regression은 가장 최근 릴리스와 비교해 판단하라고 했다.
- 대상: 릴리스 / 공개 OSS 저장소 / 태그·레지스트리 패키지·릴리스 객체 / 되돌릴 수 없는 게시, 높은 위험
- 적용 조건: 버전이 있는 산출물을 게시하는 모든 릴리스 요청. 직전 릴리스가 없으면 baseline 3분기(E2V-07)를 따른다.
- 사용자 기대: 직전 릴리스 대비 차등 검증의 gate 증거가 정확한 후보 SHA에 대해 갖춰지기 전에는 태그, 릴리스 PR, 게시가 없고, 확인된 regression·신규 버그는 보고 후 멈춘다.
- 실제 행동: 증류 시드(지시 사례). 세션은 NO-GO 보고 후 멈췄다.
- 원인 분류: missing / 규칙: E2V-01, E2V-10, E2V-20
- 변경: E2V-01, E2V-10, E2V-20 신설
- 일반화: global
- 재발 확인 기준: 게시 단계 ledger의 첫 행보다 앞서 G-GO 통과 행이 같은 후보 SHA로 있고, NO-GO 실행에는 태그·릴리스 PR·게시 기록이 없다.

- 일반화: global
