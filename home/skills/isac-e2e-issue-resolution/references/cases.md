### CASE-20260924-bulk-dedup-before-owners
- 상태: applied
- 출처: omp session 01a0d288 msg ff6e52cc
- 상황: 공개 저장소의 열린 이슈 전체를 처리하라는 run에서 중복 확인을 먼저 하고, 그 뒤 모든 이슈별 과정을 이슈마다 서브에이전트에 맡기며 메인은 오케스트레이션만 하도록 지시했다. 이미 열린 PR이 있는 이슈는 건너뛰고, CI까지 통과시키되 머지는 하지 않는 run이었다.
- 대상: 이슈 백로그 전체 처리 / 사용자 소유 공개 저장소(kwin-mcp) / 라벨·댓글·PR / 중간
- 적용 조건: 이슈 둘 이상을 한 run에서 해결까지 끌고 가는 경우. 머지 금지는 이 run의 지시이며 다른 run의 기본값이 아니다.
- 사용자 기대: 전체 중복 정리 → 이슈별 owner 병렬 진행, 열린 PR 존재 이슈 제외, PR까지 만들고 머지하지 않음.
- 실제 행동: 지시대로 진행됨. 중복 판정은 제목이 아니라 메커니즘으로 했다.
- 원인 분류: missing / 규칙: E2I-01, E2I-04, E2I-08, E2I-16
- 변경: 신규 규칙으로 반영
- 일반화: global
- 재발 확인 기준: 대량 run에서 owner 배치 전에 중복 정리 단계가 끝나 있고, ledger 머리에 머지 승인 여부가 적혀 있다.

### CASE-20260924-merge-authorized-batch
- 상태: applied
- 출처: omp session 01a0d288 msg abcc092b
- 상황: 수정 가능한 이슈마다 서브에이전트를 두고 분석·재현·근본 원인·구현·QA·e2e 테스트까지 하게 했다. 이전 버전 실패와 신규 버전 통과를 owner가 직접 확인한 뒤 PR을 열고, CI 통과 후 머지하고, 해결된 이슈는 알림과 함께 닫으라고 했다.
- 대상: 트리아지 끝난 이슈들의 수정·머지 / 사용자 소유 공개 저장소 / PR·머지·종료 댓글 / 중간
- 적용 조건: run 지시에 머지가 포함된 경우. 머지 범위는 지시가 지목한 이슈들이다.
- 사용자 기대: 수정 → 증명 → PR → CI → 머지 → 종료 댓글과 닫기가 한 run에 이어진다.
- 실제 행동: 세 이슈가 머지되고 종료 댓글과 함께 닫혔다.
- 원인 분류: missing / 규칙: E2I-01, E2I-06, E2I-14
- 변경: 신규 규칙으로 반영
- 일반화: global
- 재발 확인 기준: 머지 승인 run에서 머지된 이슈가 종결알림 없이 열린 채 남지 않는다.

- 대상: 이슈 백로그 해결 / 사용자 소유 공개 저장소(flareway) / PR·리뷰·머지 / 높음(컨트롤러 동작)
- 적용 조건: 멀티 에이전트 모드에서 이슈 여러 개를 PR·머지까지 끌고 가는 경우.

- 실제 행동: 지시대로 진행됨.
- 원인 분류: missing / 규칙: E2I-06, E2I-08, E2I-09, E2I-12
- 변경: 신규 규칙으로 반영(단계 내부 규칙은 TRI-09, TRI-18, I2P-14, I2P-22, I2P-52, MAC-18 참조)
- 일반화: global
- 재발 확인 기준: 메인이 이슈를 직접 고치지 않고, 미재현 이슈가 PR 단계로 가지 않는다.
