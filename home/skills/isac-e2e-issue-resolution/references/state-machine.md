# 이슈별 상태 기계 (E2I-06, E2I-07이 읽는다)

전이 조건과 종착 상태만 적는다. 각 단계 안의 절차와 게시물 내용·형식은 괄호 안 step 스킬 규칙이 소유한다. 여기서 다시 쓰지 않는다.

## 단계와 전이 게이트

| 전이 | 넘어가려면 참이어야 하는 것 | 못 넘으면 |
|---|---|---|
| intake → 중복정리 | E2I-01 범위 기록 완료 | 모르는 범위만 묻고(DBR-12) 확정된 대상은 진행 |
| 중복정리 → 트리아지 | 정본 판정 완료(TRI-04, TRI-41). 대량 run이면 전체 열린 이슈 기준(E2I-04) | 중복 → 종착 `중복` |
| 트리아지 → 수정 | 재현됨(TRI-07/08), 판정이 우리 코드 결함(TRI-51, TRI-22), 근본 원인 합의(TRI-17, TRI-18), 수정 방향 확정 `triage:fix-direction-decided`(TRI-28) 또는 승인된 구조 변경, 열린 PR 없음(I2P-02). 진입 조건 전체는 I2P-01 | 아래 종착 표 |
| 수정 → 리뷰 | QA list 전 항목 실행·코드화(I2P-24, I2P-33), old 실패/new 통과(I2P-25), 독립 교차 리뷰(I2P-32), PR 열림(I2P-41~45), CI green(I2P-46) | owner가 수정 반복. 외부 원인이면 `외부 블로커`(I2P-50) |
| 리뷰 → 머지 | 현재 head에 `isac-pr-review` 판정 `GREEN`·`PR-ready: true`(PRR-24), 리뷰-GREEN 루프 종료(MAC-16), 제보자 동등 환경 검증(I2P-52) | `BLOCKING` → owner에게 되돌림(MAC-18). head가 바뀌면 재판정(PRR-37) |
| 머지 → 종결알림 | E2I-01 머지 승인이 이 이슈를 포함, 전역 머지 가드 충족, 머지 완료 | 승인 없음 → 종착 `PR 준비됨(머지 미승인)` |
| 종결알림 → 종착 | 종료 댓글 게시와 이슈 닫힘 확인(I2P-57, I2P-58), 게시 후 다시 읽기(GHP-15) | 제보자 반박 → 다시 열고 트리아지로(I2P-57) |

## 종착 상태

게시물은 게시 모드일 때만 나간다(GHP-01). 초안 모드면 같은 내용을 초안으로 두고 보고에 적는다.

| 종착 | 진입 조건 | 게시물(소유 규칙) | 이슈 상태 |
|---|---|---|---|
| `중복` | 메커니즘 기준 중복 확인(TRI-41) | 정본 링크와 근거 댓글, `duplicate` 처리(TRI-04, TRI-28) | 열어 둠. 닫기는 사용자 지시 시(TRI-01), 아니면 최종 보고에 닫기 권고 |
| `미재현` | 재현 시도 실패, 제보자에게 더 요청할 정보 없음(TRI-09) | 시도한 버전·환경·절차와 관찰 댓글, `repro:not-reproduced` 후 멈춤(TRI-09, TRI-30) | 열어 둠 |
| `정보 필요` | 재현이나 판정에 제보자 정보가 필요해 요청을 게시함(TRI-43, TRI-09). 두 라벨이 함께 붙어도 ledger 종착은 이것 하나 | 필요한 정보와 안전한 진단 명령 요청, `triage:needs-info`(TRI-43, TRI-28) | 열어 둠 |
| `의도된 동작` | 결함이 아님(TRI-51, TRI-13), 또는 사용자가 넣지 않은 기능·제안 이슈(TRI-03) | 판정 근거 댓글(TRI-30). 개선 후보면 개선 방향(TRI-13) | 사용자 지시가 있을 때만 닫음(TRI-01) |
| `구조 변경 승인 대기` | 근본 해결이 프로젝트 핵심 변경(TRI-25, I2P-14) | 분석 댓글과 `triage:needs-structural-change`, 브리프는 최종 보고(E2I-12) | 열어 둠, 승인 시 수정부터 재개 |
| `기존 PR 있음` | 열린 PR이 이미 있음(I2P-02, TRI-42) | 그 PR이 못 푸는 잔여 결함 댓글(TRI-42), 없으면 게시 없음 | 열어 둠 |
| `PR 준비됨(머지 미승인)` | 리뷰→머지 게이트 통과, 머지 승인 없음 | PR과 리뷰 이벤트(PRR-25). 이슈에 추가 게시 없음 | PR 열림, 이슈 열림 |
| `머지·종결됨` | 종결알림 완료 | 종료 댓글(I2P-57, I2P-58). 미릴리스면 표기(I2P-60, E2I-15) | 닫힘 |
| `외부 블로커` | upstream·환경 원인(TRI-22, TRI-06), 자격증명·권한 부족(DBR-18), CI 외부 요인(I2P-50) | upstream 추적 정보 또는 차단 사유 댓글(TRI-06, TRI-30). 자격증명 요청은 사용자 보고로만 | 열어 둠 |

## 되돌림

- 리뷰 `BLOCKING`, CI 실패, QA 실패는 종착이 아니다. 같은 owner가 같은 절차를 반복한다(MAC-16, I2P-47).
- 사용자 결정(구조 변경 승인, 범위 선택)이 오면 그 이슈만 해당 단계부터 재개하고 ledger에 결정을 적는다.
- 머지 뒤 제보자 환경에서 재발하면 이슈를 다시 열고 트리아지로 돌린다(I2P-57).
- `정보 필요`, `미재현`, `외부 블로커` 이슈는 제보자 정보가 오거나 블로커가 풀리면 그 이슈만 `트리아지`(재현)부터 다시 시작하고 ledger에 전이를 적는다. 다른 이슈에는 영향이 없다. 이전 run에서 이 라벨을 달고 남은 이슈는 intake에서 보통 대상으로 받되, 새 정보가 있을 때만 다시 트리아지한다(TRI-02 재조회).
