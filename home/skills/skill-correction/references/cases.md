### CASE-20260925-repo-pref-memory-only
- 상태: applied
- 출처: omp session 01a0d288 msg 7449e495
- 상황: 특정 저장소에서만 쓰는 머지 선호(작성자 본인 PR은 관리자 머지 기본)를 에이전트가 영구 지침 원본과 저장소 AGENTS.md에 넣었다(예: kwin-mcp).
- 대상: 교정 영속화 / 사용자 소유 공개 저장소 / 공유 지침 파일·전역 지침 / 중간(모든 에이전트와 세션에 퍼지는 쓰기)
- 적용 조건: 교정 내용이 한 저장소·대상에만 적용되는 사용자 작업 방식 선호일 때. 레지스트리 규칙을 저장소와 무관하게 바꾸는 교정에는 적용하지 않는다.
- 사용자 기대: 사용자·저장소 한정 선호는 memory에만 둔다. 공유·커밋되는 지침과 범용 스킬에는 넣지 않는다.
- 실제 행동: 전역 지침과 저장소 지침 파일을 수정했다.
- 원인 분류: missing / 규칙: SKC-11
- 변경: 신규 → 반영 위치 분류에 "사용자·저장소 한정 선호 → memory만" 추가
- 일반화: global
- 재발 확인 기준: 작업 방식 선호를 교정할 때 제안의 반영 위치가 memory이고, 스킬 본문·프로젝트 reference·지침 파일 diff가 없다.
- 비고: 선호 자체의 반영 위치는 memory다. 이후 사용자가 이 선호를 저장소 하나가 아니라 `isac322` 소유 저장소에서 `isac322`가 작성한 PR 전체의 전역 머지 기본값으로 넓히라고 결정했다(01a0dda6 84a012fa 이후 후속 답). 그래서 관리자 머지 기본값은 전역 `pull-request-merge-authorization` segment에 있고, 이 케이스의 규칙(한 저장소 한정 선호는 memory)은 그대로 유효하다.

### CASE-20260925-revert-wrong-location
- 상태: applied
- 출처: omp session 01a0d288 msg 103d1411
- 상황: 저장 위치가 틀렸다는 지적을 받은 뒤 올바른 위치에 저장하는 것만으로는 부족했다.
- 대상: 교정 영속화 / 저장소 무관 / memory·지침 파일·스킬 파일 / 중간(잘못된 위치의 지침이 계속 로드됨)
- 적용 조건: 사용자가 저장 위치가 틀렸다고 지적한 모든 교정
- 사용자 기대: 잘못 넣은 변경을 먼저 되돌리고 올바른 위치에 다시 저장한 뒤, 무엇을 어디에 넣고 무엇을 되돌렸는지 정확히 보고한다.
- 실제 행동: 되돌림과 재저장을 사용자가 명시적으로 다시 지시해야 했다.
- 원인 분류: missing / 규칙: SKC-12
- 변경: 신규 → 위치 교정은 되돌리기 → 재저장 → 보고 순서
- 일반화: global
- 재발 확인 기준: 위치 교정 결과 보고에 되돌린 위치와 새 위치가 모두 나온다.

### CASE-20260925-correction-not-persisted
- 상태: applied
- 출처: omp session 01a0d288 msg ASK@2026-09-25T15:58 (선행 승인 ASK@2026-09-25T10:09)
- 상황: 같은 세션에서 같은 종류를 이미 허용했는데도, 에이전트가 승인된 머지의 부수 단계(저장소 기본값인 브랜치 삭제)를 다시 물었다. 사용자가 같은 종류의 질문을 하지 말고 처리하라고 여러 번 교정했지만 그 교정이 어디에도 영속화되지 않았다.
- 대상: 장시간 자율 작업 중 교정 / 사용자 소유 공개 저장소 / 사용자 질문 / 낮음(되돌릴 수 있지만 작업 흐름을 끊음)
- 적용 조건: 사용자가 작업 중 교정을 주고 같은 세션이나 이후 위임에 같은 종류의 판단이 다시 올 때
- 사용자 기대: 교정은 즉시 현재 작업의 standing constraint가 되고, 사용자가 반영을 요청하면 `skill-correction` 경로(스킬 PR 또는 memory)로 영속화되어 같은 질문·실수가 반복되지 않는다.
- 실제 행동: 같은 세션에서 이미 승인한 것과 같은 종류의 질문을 반복했다.
- 원인 분류: missing / 규칙: SKC-02
- 변경: 신규 → 지적 즉시 현재 작업에 반영하고 교정 절차가 원 작업을 막지 않게 함(전파는 `multi-agent-consensus`, 재질문 기준은 `decision-brief`)
- 일반화: global
- 재발 확인 기준: 교정 뒤 같은 세션과 이후 위임에서 같은 종류의 질문이 나오지 않는다.
- 비고: 질문 여부 기준 자체는 `decision-brief`가 소유한다. 여기서는 교정을 영속화하지 않은 점만 다룬다.

### CASE-20260917-loose-evidence-rule
- 상태: applied
- 출처: omp session 01a0ae59 msg ef4fba96
- 상황: 이슈 판정 스킬이 코드 분석만으로도 확정 판정을 허용했다(예: flareway 이슈 처리).
- 대상: 버그 이슈 판정 / 공개 저장소 / 공개 판정 댓글·라벨 / 높음(틀린 판정이 공개됨)
- 적용 조건: 사용자 교정으로 증거 기준이 정해진 규칙을 고치거나 옮기는 모든 교정
- 사용자 기대: 확정 판정은 실제 코드 실행 재현이 필수이고, 외부 의존성은 공식 문서·스펙에 근거한 계약 준수 mock으로만 대체한다.
- 실제 행동: 코드와 제보 로그만 보고 판단하는 경로가 규칙상 열려 있었다.
- 원인 분류: loose / 규칙: `issue-validation` 재현 기준(당시 코드 분석만으로 확정 판정을 허용). 교정 쪽 교훈은 SKC-09로 반영
- 변경: 신규 → 사용자 기준보다 느슨한 규칙은 사용자 기준으로 강화하고, 교정으로 확정된 증거 기준은 완화하지 않는다
- 일반화: global
- 재발 확인 기준: 증거 기준 교정의 변경안이 사용자 문언의 기준을 그대로 옮기고, 이후 해당 스킬 실행에서 실행 재현 없는 확정 판정이 없다.
- 비고: 증거 기준 본문은 `issue-validation`이 소유한다.

### CASE-20260927-context-free-generalization
- 상태: applied
- 출처: omp session 01a0dda6 msg 33d72f67
- 상황: 스킬 증류 중 에이전트가 과거 세션의 짧은 머지 지시 한 줄을 어떤 상황·대상이었는지 확인하지 않고 스킬 기본값으로 만들려고 해석 선택지만 물었다.
- 대상: 스킬 증류·교정 / 여러 저장소(소유권 다양) / 스킬 규칙 / 높음(머지 같은 되돌리기 어려운 행동의 기본값)
- 적용 조건: 사용자 발화를 스킬 규칙이나 기본값으로 옮기는 모든 증류·교정
- 사용자 기대: 규칙은 그 발화가 나온 상황과 대상(작업, 저장소 소유권, 산출물, 위험도)과 함께 도출하고 적용 조건을 밝힌다. 일회성 지시는 케이스로만 남긴다.
- 실제 행동: 발화 하나를 맥락 없이 일반화하려 했고, 해석 질문에도 원래 상황을 제시하지 않았다.
- 원인 분류: missing / 규칙: SKC-34
- 변경: 신규 → 규칙 도출에 상황·대상과 적용 조건을 요구하고, 분석 결과와 케이스 스키마에 해당 필드 추가
- 일반화: global
- 재발 확인 기준: 교정·증류 제안마다 적용 조건 줄이 있고, 근거가 발화 하나뿐인 규칙은 상황·대상을 함께 제시하거나 케이스로만 남는다.
