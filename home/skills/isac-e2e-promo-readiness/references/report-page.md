# Steering report page (E2R-17 ~ E2R-19, E2R-25, E2R-26)

오너가 자기 기기에서 열어 계획·증거·진행 상황을 보고 방향을 정하는 정적 페이지. 오너 언어로 쓴다. 이 페이지는 내부 steering 도구이며 공개 사이트나 repo에 들어가지 않는다(E2R-38).

## 위치와 서빙

- 디렉터리: repo 밖, 세션이 끝나도 남는 경로(예: `~/<project>-promo/report/`). 프리뷰 빌드와 비교 페이지는 형제 디렉터리에 둔다(`preview/`, `round-N/`).
- 서빙: 오너 기기에서 닿는 인터페이스에 바인딩한 정적 서버를 장기 서비스로 띄운다. 예) `bunx serve -l tcp://<reachable-ip>:<port> <dir>`, 없으면 `python3 -m http.server <port> --bind <reachable-ip> --directory <dir>`. 포트가 막히면 다음 포트로 바꾸고 ledger에 기록한다.
- 도달 가능한 주소: 오너가 쓰는 LAN·VPN 주소나 오너 계정으로만 열리는 터널. 신뢰할 수 없는 네트워크에 `0.0.0.0`으로 열지 않는다. 시크릿·토큰·개인 경로를 페이지에 넣지 않는다.
- 전달 전 확인: 그 주소로 `curl -sI`가 200인지, 브라우저 도구로 데스크톱 폭과 모바일 폭(약 360–390 px) 렌더링, 모든 내부 링크 200, 썸네일·이미지 로드. 파일 경로(`/tmp/...`, `file://`)는 주지 않는다.

## 구조

1. 요약 헤더: 목표 / 지표 / 방향 세 줄, 마지막 갱신 시각.
2. 진단: 현재 표면의 문제와 증거 링크.
3. 지표 표: baseline → target, 출처 API.
4. 방향: 포지셔닝 한 문장, 랜딩 와이어프레임(SVG), 팔레트 견본, H1 후보.
5. 작업 표: `status.json`에서 렌더링(id, 작업, owner, status, 산출물·PR 링크, 막힌 이유). ledger와 같은 원본.
6. 오너 질문: "확인 부탁드립니다" 표시, 선택지와 권장안(`isac-decision-brief`).
7. steering 라운드 절: 라운드마다 "N차 교정 반영" — 오너 원문, 바뀐 결정, revision brief 링크.
8. 현재 상태와 남은 승인: 머지 대기 PR, 외부 적용 대기, blocked.
9. 비교 페이지 링크: 디자인 라운드별 인덱스.
10. 리서치 원문 링크(`research/*`).

## 비교 페이지

- `round-N/index.html`: 변형을 나란히, 변형마다 라이브 프리뷰 링크와 데스크톱·모바일·다크/라이트 스크린샷, 한 줄 차이 설명.
- 로고·아이콘 비교는 제품 맥락 속 배치(런처·독·브라우저 탭·README 헤더·패키지 배지 행 등)와 크기 사다리(예: 128/64/32/16 px, 라이트·다크)를 포함한다(세부는 BRD).
- 모션·데모 비교는 브라우저에서 재생되는 영상과 수치 안정성 지표(떨림 px, 역전 횟수 등)를 함께 둔다(세부는 MED). 사용자가 구분할 수 없는 변형은 잘라낸다.
- 이전 라운드는 지우지 않는다. 인덱스에서 모든 라운드로 이동할 수 있다.

## 갱신

- 합의, steering 라운드, 디자인 라운드, 머지, 배포, 감사 때마다 갱신하고 헤더 시각을 바꾼다.
- 모든 승인 질문과 진행 보고에 리포트 URL(필요하면 해당 절 앵커)을 넣는다.
- 최종 감사(E2R-42) 때 리포트가 최종 상태를 반영하는지 함께 확인한다. 오래된 리포트는 감사 결함이다.
