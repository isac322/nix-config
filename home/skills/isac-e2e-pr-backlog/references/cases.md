### CASE-20260917-sequential-update-merge
- 상태: applied
- 출처: omp session 01a0ae59 msg 4a8b7d69
- 상황: 여러 에이전트 PR이 열려 있고 머지할 때마다 나머지가 outdated되는 상황에서, 사용자는 PR을 최신화하고 CI가 통과하면 하나씩 머지하고 CI가 실패하면 통과하게 고치라고 했다.
- 대상: 열린 PR 여러 개의 순차 머지 / 사용자 소유 공개 저장소(flareway) / PR 브랜치 push와 머지 / 중간
- 적용 조건: 한 실행에서 머지가 허용된 PR이 둘 이상이고 서로 같은 main을 공유할 때. 머지 권한 자체는 그 실행의 지시에서 온다.
- 사용자 기대: 최신화 → CI green → 머지를 한 번에 하나씩 반복하고, 실패한 CI는 원인을 고쳐 통과시킨다.
- 실제 행동: 순차 처리 규칙이 없어 머지 순서와 최신화 시점이 에이전트 판단에 맡겨져 있었다.
- 원인 분류: missing / 규칙: I2P-54 (E2P-07은 참조)
- 변경: 규칙 유지, 케이스 기록(순차 머지 규칙의 owner는 `isac-issue-to-pr` I2P-54)
- 일반화: global
- 재발 확인 기준: ledger에 PR마다 최신화 SHA, CI 결과, 머지 커밋, 머지 뒤 main CI가 순서대로 기록된다.

### CASE-20260916-unrelated-drift-before-merge

- 대상: 머지 시 적용 계획이 도는 인프라 PR / 조직 비공개 저장소 / plan·apply·머지 / 높음(무관한 인프라 변경 적용)

- 실제 행동: 무관한 drift가 섞인 계획을 들고 진행 여부를 물었다.
- 원인 분류: missing / 규칙: E2P-09

- 변경: 신규 규칙으로 시드(닫기 부분은 GHP-12·PRR-02 참조)

### CASE-20260926-subset-pr-first
- 상태: applied
- 출처: omp session 01a0d288 msg 2b0b0c0a
- 상황: 감사 뒤 "수정 push 완료, 머지 대기" PR 여러 개가 같은 문제를 겹쳐 겨냥했다. 사용자는 모두 검증돼 머지만 남았다면 더 작은 subset PR을 먼저 머지하고, 나머지는 main으로 올려 CI를 통과시키고 이미 머지된 subset 내용은 빼라고 했다.
- 대상: 겹치는 PR 묶음의 머지 순서 / 사용자 소유 공개 저장소(kwin-mcp) / 머지와 PR 브랜치 수정 / 중간
- 적용 조건: 같은 실행에서 검증을 마친 PR들이 같은 문제를 겹쳐 겨냥할 때. 사용자가 다른 순서를 주면 그것을 따른다.
- 사용자 기대: subset 먼저 머지, superset은 최신화 후 중복 내용을 빼고 재검증해 머지.
- 실제 행동: 겹침 관계를 기록하지 않았고, CI가 통과하지 않은 PR도 "머지 직전"으로 분류돼 있었다.
- 원인 분류: missing / 규칙: E2P-05, E2P-06, E2P-07
- 변경: 신규 규칙으로 시드
- 일반화: global
- 재발 확인 기준: ledger에 겹침 관계가 있고, 머지 순서가 subset 먼저이며, CI green 전인 PR은 머지 직전 단위에 없다.

- 사용자 기대: 중복 내용을 PR에서 제거하고 남은 범위만 다시 리뷰해 머지.
- 실제 행동: 중복 포함 상태로 보고만 했다.
- 원인 분류: missing / 규칙: E2P-06
- 변경: 신규 규칙으로 시드
- 일반화: global
- 재발 확인 기준: 머지된 PR의 최종 diff에 이미 main에 있던 변경이 없고, 좁힌 뒤 리뷰 결과가 따로 있다.

### CASE-20260926-dependabot-order-this-run

- 대상: 의존성 업데이트 봇 PR / 사용자 소유 공개 저장소(kwin-mcp) / 머지 / 중간
- 적용 조건: 순서("가장 먼저", "바로")는 이 사례 한정이다. rebase 완료 대기와 앱 동작 확인은 의존성 봇 PR 머지 전반에 적용한다.
- 사용자 기대: 지시한 순서로 처리하되, 봇 rebase가 끝난 head에서 앱이 깨지지 않음을 확인하고 머지.
- 실제 행동: 봇 PR 처리 기준이 없었다.
- 원인 분류: missing / 규칙: E2P-10, E2P-01
- 변경: E2P-10 신규(검증 부분), 순서는 E2P-01의 실행별 우선순위로만 둔다
- 일반화: global
- 재발 확인 기준: 봇 PR 머지 기록에 rebase 후 head SHA와 앱 동작 확인이 있고, 순서 지시가 없는 실행에서 봇 PR을 임의로 먼저 머지하지 않는다.

- 대상: 필수 사람 승인이 걸린 PR 머지 / 사용자 소유 공개 저장소(kwin-mcp) / 머지 방식 / 높음(보호 규칙 우회)

- 일반화: global
- 비고: 작성자 기준 관리자 우회 기준은 전역 머지 가드로 옮겨졌다. 스킬에는 기준을 다시 쓰지 않는다.
- 재발 확인 기준: ledger에 PR별 머지 방식 근거(전역 가드 기본값 / 이번 승인)가 있고, 가드 기본값이 적용되는 PR에 우회 승인 질문이 없다.
