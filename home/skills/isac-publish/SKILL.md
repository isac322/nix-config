# GitHub Publishing

GitHub에 쓰는 모든 행위의 공통 절차. 각 호출 스킬(`isac-triage`, `isac-fix`, `isac-review`, `isac-live-qa`, `isac-correct`)은 내용·판정·템플릿·라벨 의미를 소유하고, 이 스킬은 게시 절차만 소유한다. PR 생성·머지·리뷰 대응의 승인과 필수 메타데이터는 전역 pull-request 가드가 소유한다.

## 순서

1. 모드 확정(GHP-01) → 2. 게시 주체 확인(GHP-15) → 3. 초안 작성(GHP-02~07, `references/style.md`) → 4. 게시 직전 상태 재확인·중복 확인·sanitize 체크리스트(GHP-08~10) → 5. 게시·라벨(GHP-11, GHP-14) → 6. 다시 읽어 대조 후 최종 보고: 게시 URL, 만든 라벨, 라벨 매핑, 초안 모드면 “게시 가능” 한 줄(GHP-12, GHP-15).

## 모드

- **GHP-01** 전역 `task-intent-boundary`가 우선한다. 사용자가 스킬을 명시 호출하거나 게시 동사(“달아”, “올려”, “라벨 붙여”, “이슈 만들어”, “코멘트 남겨”)로 요청하면 그 대상의 게시가 승인된 것이고, 분석만 요청(“분석해봐”, “리뷰해봐”, “확인해”)이면 초안만 만들고 최종 보고에 게시 가능함을 한 줄로 알린다. 초안 모드에서는 어떤 GitHub 쓰기(댓글, 라벨 생성·교체, 이슈 생성·수정·종결)도 하지 않는다. 이 모드는 PR 생성·머지 승인을 대신하지 않는다.

## 언어와 문체

- **GHP-02** [U] GitHub 대화 산출물(이슈, 댓글, 리뷰 댓글, PR 제목·본문, 라벨 이름·description, 릴리스 노트)은 **영어**로 쓰고, 사용자와의 대화·보고는 한국어로 한다. 이슈·댓글·리뷰 댓글·라벨 description은 핵심만 담아 아주 간결하게 쓰고, PR 본문은 길어도 된다.
- **GHP-03** [U] 공개 텍스트 작성에는 `writing-clearly-and-concisely`와 `humanizer` 스킬을 반드시 적용한다. 문체 세부는 그 스킬들이 소유하며 여기서는 호출만 한다.
- **GHP-04** 공개 댓글에는 `comment-writer` 스킬도 적용한다.
- **GHP-05** 판정·결론을 글 맨 앞에 두고, 이어서 근거(무엇을 어느 버전·환경에서 실행했고 무엇이 관찰됐는지)를 적는다. 세부 구조·템플릿·길이 예산은 각 호출 스킬이 소유한다(기본값은 `references/style.md`). 큰 구조 변경 PR이면 본문에 전반 구조·방향·설계를 적는다(사족 없이). 커밋되는 코드·문서는 저장소의 기존 언어 규약을 따르고, 규약이 없으면 영어로 쓴다. 제품·리소스 식별자는 영어 원문을 유지한다.
- **GHP-06** 실행하지 않은 검증·재현은 실행한 것처럼 쓰지 않는다. 아직 실행 전인 것은 “pending”으로 표시하고 공개하지 않으며, 추론·측정하지 않은 주장은 `[INFERENCE]` 등으로 표시한다. 지어낸 사실·존재하지 않는 근거·과장 표현을 쓰지 않는다(정직 근거는 전역 `verification` 가드 소유).
- **GHP-07** 호출 스킬이 판정한 분류(결함 vs 개선 요청)를 제목·본문·라벨에 그대로 반영하고, 잠재적 문제를 입증된 장애로 부풀리지 않는다.

## 위생 (sanitize)

- **GHP-08** 공개 본문에 비공개 정보를 넣지 않는다. 대상 저장소의 공개 여부와 무관하게 모든 GitHub 텍스트에 적용한다. 실환경 값은 `example.com`, `<zone-id>` 같은 합성 값으로 바꾸고, 버전·고정 SHA·pinned 링크를 명시한다. 금지 항목과 게시 전 체크리스트는 `references/sanitize.md`를 따른다. 사용자와의 비공개 대화에서는 실제 이름을 써도 된다.

## 중복·수정·추적

- **GHP-09** 게시 직전에 현재 상태를 다시 확인한다. 이슈 생성 전에는 open·closed 전체를 검색하고(`gh issue list -R <owner>/<repo> --state all --search "<keywords>"`), 중복이면 만들지 않고 그 URL을 보고한다. 댓글은 대상의 기존 댓글을 확인해 중복 게시를 막는다. 관련된 닫힌 선행 작업(이전 fix PR, 설계 문서)은 복제하지 않고 참조한다.
- **GHP-10** [U] 게시하려는 내용과 관련된 기존 이슈·PR이 이미 있을 때(GHP-09로 확인): 이미 반영돼 있으면 건너뛰고, 아니면 새 이슈를 만들지 않고 그 이슈·PR을 보강한다(댓글, 본문 수정, 코드 push). 관련 대상이 없으면 새로 만든다.
- **GHP-11** 보강은 본문·댓글 제자리 수정을 우선한다. 같은 스킬의 분석 댓글은 대상당 하나를 유지하고, 판정이 바뀌는 후속 사건(수정 머지·릴리스·종결)은 짧은 새 댓글로 남긴다. 사용자가 준 문구나 승인된 초안 문구는 그대로 쓴다. 고칠 대상인 자기 산출물(댓글·이슈·PR)은 작성자(`gh api user --jq .login`과 author 비교)와 이번 세션의 게시 기록으로 식별하고, 이전 세션 것은 부모 세션의 실제 실행 기록으로 확인한다(서브에이전트 초안이나 빈 검색 결과만으로 단정하지 않는다). 자신이 만든 산출물(이슈·PR·브랜치·댓글)은 추적하고 게시 후 URL을 수집해 “네가 만든 거야?”에 답할 수 있게 한다.
- **GHP-12** [U] 에이전트가 만든 이슈·PR을 사용자가 “제거”하라고 하면 삭제하지 않고 close한다.
- **GHP-13** 공개 글에서 이전에 잘못 쓴 내용은 명시적으로 정정하고 본문도 고친다. 닫힌 이슈의 오래된 종료 주장이 새 검증으로 바뀌면 증거 댓글로 보정하되, 사용자가 직접 닫은 이슈·PR은 지시 없이 다시 열지 않는다. 인용 증거는 의미가 바뀌게 잘라내지 않는다.

## 라벨

- **GHP-14** 라벨의 조회·의미 매핑·생성·상호배타 교체 메커닉은 이 스킬이 소유하고(`references/labels-mechanics.md`), 라벨 이름·설명·색·배타성·부착 기준은 호출 스킬이 소유한다. 게시 모드에서만 라벨을 만들고, 같은 의미의 기존 라벨이 있으면 그것을 우선한다. 기존 라벨의 rename·recolor·delete는 하지 않는다.

## 게시 주체

- **GHP-15** GitHub에는 지정된 게시 주체 하나만 쓴다. 기본은 메인(부모) 에이전트다. 사용자나 호출 스킬이 서브에이전트를 게시 주체로 지정할 수 있고(예: `isac-live-qa`의 finding 담당자, 항목별 작업을 댓글·PR까지 서브에이전트에 맡기라는 사용자 지시), 그 주체도 이 스킬의 절차를 따른다. 게시 주체가 아닌 에이전트·헬퍼는 초안만 만든다. 게시 전에는 초안 작성자가 아닌 독립 검토자가 초안의 주장을 실행 결과와 대조하고(단독 작업이면 게시 주체가 수행), 게시 후에는 `gh issue view`/`gh pr view --json body,comments` 또는 `gh api`로 다시 읽어 승인된 초안과 같은지 확인한다.

---

결과가 사용자 기대와 다르면 `isac-correct` 스킬로 교정할 수 있다. 실행 도중 사용자가 이 스킬의 동작을 교정했다면 최종 보고에 한 줄로 알린다(실행 도중 따로 묻지 않는다).
