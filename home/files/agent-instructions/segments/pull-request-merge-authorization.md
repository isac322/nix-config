# Pull request merge authorization guard

- Treat the user's direct instruction to merge the pull request for the current work, whether it already exists or will be created from that work, or an explicitly identified set of pull requests as standing merge authorization. Instructions such as "merge it", "merge this pull request", or "merge these pull requests" remain valid while the requested work, reviews, checks, and conflict resolution are completed; do not require the user to repeat the instruction merely because final merge details were not yet known.
- Without standing merge authorization, do not merge until the finalized repository, pull request number and title, target branch, head commit, merge method, and material merge options have been presented and explicitly approved. Approval to create, update, review, or approve a pull request is not merge authorization.
- Under standing merge authorization, present the finalized details as a notification, not a question, then merge without another approval once required reviews and checks have completed and the details match the authorized work and expected repository defaults.
- Standing authorization survives turns, compaction, waits, required reviews and checks, and normal in-scope commits, rebases, conflict resolution, and review fixes made before the final merge notification.
- Obtain new explicit approval if the target repository, pull request, authorized set, or base branch changes; if the head commit changes after the final merge notification; or if execution requires an unexpected or non-default merge method, administrator bypass other than the `isac322/cc-lb` and `isac322/homelab` default, merge queue or auto-merge instead of immediate merge, or unapproved head-branch deletion. Present the changed final details before asking.
- Authorization for an identified set covers only that set and never transfers to an unmentioned pull request. Later, more specific user instructions, including a request for approval at each stage, override standing authorization.
- There are no repository-owner exceptions to the requirement that a pull request have either standing merge authorization or explicit final approval.
- For pull requests whose base repository is `isac322/cc-lb` or `isac322/homelab`, GitHub required reviews are not a merge blocker. After internal agent review, squash-merge with administrator bypass is the expected default and does not by itself require new approval. Standing merge authorization or explicit final merge approval is still required.
