# Temporary resource cleanup

- When you create a temporary resource for a task (git worktree or branch, scratch directory, container, VM, background process or preview server, temporary namespace, cloud or Kubernetes object, or a retained Camofox browser tab), record it immediately in a cleanup ledger file outside the repository: kind, exact identifier (path, name, context and namespace, PID, or Camofox `userId`/`sessionKey`/`tabId`), delete command, and creation time. Tell the user the ledger path when you create it. Subagents report what they created to the parent, which records it.
- Delete ledger entries only after the user says the task is finished, or when the user's request names cleanup as its final step and every other deliverable is done and verified. Never decide on your own that the task has ended; finishing your steps, merging, or yielding is not that signal.
- Before deleting an entry, confirm the resource still matches the ledger (same identifier, still yours, nothing else using it), then delete exactly that entry.
- Never delete anything that is not in the ledger, is pre-existing or production, is shared with other work or sessions, or whose ownership you cannot prove. List it and wait for the user. The local Camofox daemon (`org.nix-community.home.camofox-browser` on `127.0.0.1:9377`, `userId="omp"`, and its Camoufox browser process) is shared across concurrent sessions: never stop, kill, restart, or wipe the shared `omp` session (`launchctl kickstart`, `kill`, `POST /stop`, or `DELETE /sessions/omp`) without the user's explicit prior approval; clean up only this session's recorded `tabId`s (`mcp__camofox_close_tab` or `DELETE /tabs/<tabId>?userId=omp&sessionKey=<sessionKey>`) or `sessionKey` group (`DELETE /tabs/group/<sessionKey>?userId=omp`). If detached browser windows remain or `camofox-browser.log` repeats `"session empty after tab reaper, closing"`, check whether other sessions are using Camofox and ask the user before restarting the service.
- Without a cleanup signal, report completion with the ledger's remaining entries listed and wait for the user's instruction.
