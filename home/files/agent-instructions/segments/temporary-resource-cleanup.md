# Temporary resource cleanup

- When you create a temporary resource for a task (git worktree, branch, fetched temporary ref such as `refs/tmp/*`, or stash; scratch directory or file; container, VM, or local database cluster; background process or preview server; temporary namespace; cloud or Kubernetes object; or a retained Camofox browser tab), record it in the cleanup ledger before or in the same command that creates it: kind, exact identifier (path, name, context and namespace, PID, or Camofox `userId`/`sessionKey`/`tabId`), delete command, and creation time. Tell the user the ledger path when you create the ledger.
- Keep the ledger at `~/.cache/cleanup-ledgers/<workspace>--<task>.ledger`, where `<workspace>` is the basename of the session's working directory and `<task>` is a short slug. Never put it in `/tmp`, in the repository, or inside a scratch directory it tracks: deleting that directory must not delete the records of other resources. A later task in the same session or workspace that continues the work keeps appending to the same ledger.
- The ledger is append-only. Add an entry by appending (`>>` or append mode), and record a deletion by appending a `removed <identifier> <time>` line. Never rewrite, truncate, or replace the file with a whole-file write, and never write to a ledger that another session owns.
- A scratch file is any file you write outside the repository that is not a deliverable the user asked to keep, including redirected command output and logs (`> /tmp/x.log`, `tee`), drafts such as PR or issue bodies passed to `--body-file`, and downloaded or generated fixtures. Write these inside one recorded scratch directory for the task when you can, so a single entry covers them; otherwise record each file before or in the same command that creates it.
- Only the top-level agent writes its ledger. In-process subagents never create, write, or edit any ledger, including the parent's: each delegated task that may create resources must tell the subagent to list every resource it created (with the fields above) in its final result and must not ask it to keep a ledger. The parent appends those entries as soon as the result arrives, before doing anything else. A separate top-level session that you start (for example an Orca child session) keeps its own ledger under the same directory; record that ledger's path in your ledger as a `child-ledger` entry when you start the session.
- Delete ledger entries only after the user says the task is finished, or when the user's request names cleanup as its final step and every other deliverable is done and verified. Never decide on your own that the task has ended; finishing your steps, merging, or yielding is not that signal.
- To clean up, collect every open entry (added and not yet `removed`) from every ledger matching `~/.cache/cleanup-ledgers/<workspace>--*.ledger`, not only the current task's, and from every `child-ledger` they list. Before reporting cleanup complete, sweep for unrecorded leftovers: the workspace's extra git worktrees, branches, `refs/tmp` refs, and stashes; scratch paths under `/tmp` and `/data/tmp` named after the task; containers; and listening or background processes started from the task's paths. Report every finding with its ownership evidence and handle it under the rules below; never report cleanup as complete while a finding is unresolved.
- Before deleting an entry, confirm the resource still matches the ledger (same identifier, still yours, nothing else using it), then delete exactly that entry.
- Never delete anything that is not in the ledger, is pre-existing or production, is shared with other work or sessions, or whose ownership you cannot prove. List it and wait for the user. The local Camofox daemon (`org.nix-community.home.camofox-browser` on `127.0.0.1:9377`, `userId="omp"`, and its Camoufox browser process) is shared across concurrent sessions: never stop, kill, restart, or wipe the shared `omp` session (`launchctl kickstart`, `kill`, `POST /stop`, or `DELETE /sessions/omp`) without the user's explicit prior approval; clean up only this session's recorded `tabId`s (`mcp__camofox_close_tab` or `DELETE /tabs/<tabId>?userId=omp&sessionKey=<sessionKey>`) or `sessionKey` group (`DELETE /tabs/group/<sessionKey>?userId=omp`). If detached browser windows remain or `camofox-browser.log` repeats `"session empty after tab reaper, closing"`, check whether other sessions are using Camofox and ask the user before restarting the service.
- Without a cleanup signal, report completion with the ledger's remaining entries listed and wait for the user's instruction.
