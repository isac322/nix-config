# Task intent boundary

- Before beginning work, classify what the current user request newly authorizes. This is a stateless decision for that request, not a persistent work mode.
- Treat a request as analysis-only when it asks to analyze, investigate, inspect, review, audit, diagnose, explain, compare, report, plan, design, propose, check, confirm, verify, find out, or look into something and contains no explicit state-changing instruction. Korean equivalents include 분석, 조사, 검토, 리뷰, 감사, 진단, 설명, 비교, 보고, 계획, 설계, 제안, 확인해, 확인해와, 확인해봐, 알아봐, 찾아봐, 살펴봐, 파악해, 점검해, and 체크해. These are semantic examples, not a closed keyword list.
- An explicit no-change marker such as "dry run", "드라이런", "분석만", "보고만", "수정하지 마", or "건드리지 마" makes the clearly scoped request analysis-only regardless of implementation language in that request. Execute only a path that provably avoids repository, system-configuration, and external semantic writes; otherwise report the intended command and effects instead of running it.
- Analysis-only requests do not newly authorize repository or configuration writes, Git writes, pull request or issue mutations, external-service writes, deployments, package installation, system switches, durable-memory writes, or edit-capable subagent assignments. Finding a fix does not authorize implementing it; deliver the findings, evidence, and proposed change.
- Read-only inspection and tests, builds, and reproductions are permitted when they leave no repository, system configuration, or external semantic state. Use no-write flags and scratch locations. Local ephemeral caches, Nix store realizations, and scratch artifacts outside the repository are permitted. If the requested analysis cannot be completed without a prohibited write, report the limitation or ask for authorization for that specific write.
- Treat an explicit instruction to fix, modify, implement, add, remove, apply, refactor, commit, push, merge, install, deploy, switch, or roll back as implementation authorization only for the named or clearly referenced scope. Korean equivalents include 고쳐, 수정해, 구현해, 추가해, 삭제해, 적용해, 반영해, 리팩터링해, 커밋해, 푸시해, 머지해, 설치해, 배포해, 전환해, and 롤백해.
- A request that explicitly combines analysis with conditional or subsequent implementation authorizes both steps. Evaluate the stated condition against the requested subject, state the result, and implement only when the condition is met and only within that scope. Report rather than fix problems outside that scope.
- When the request contains neither a clear analysis intent nor a clear state-changing instruction, or its mutation target or scope cannot be resolved from the conversation, ask whether the user wants analysis or implementation before beginning work. Ask only about mutation intent; resolve repository facts with tools.
- A follow-up such as "apply it", "fix it", "implement it", "proceed", "적용해", "고쳐", "구현해", or "진행해" authorizes implementation only when it refers to one clearly identified proposal from the preceding report. If the report offered multiple alternatives or optional changes, ask which one to apply.
- This guard controls only what the current request newly authorizes. An interleaved analysis-only request does not revoke, suspend, or narrow standing authorization previously granted for separate in-flight work. Revoke or suspend existing authorization only when the user explicitly stops, pauses, cancels, or forbids that action, such as "stop", "cancel it", "do not merge", "do not commit", "아직 적용하지 마", "머지하지 마", or "작업 멈춰". If a no-change marker's scope over separate authorized work is unclear, ask before either mutating or cancelling that work.
- Every delegated task must restate the current request's write boundary. Analysis-only requests may dispatch only read-only assignments.
- For an analysis-only request, the findings or requested report are the complete deliverable. General defaults to act, fix the source, continue actionable work, or perform cleanup do not grant implementation authorization. This guard never permits an action forbidden by a more specific approval or safety rule.
