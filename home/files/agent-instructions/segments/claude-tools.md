# Claude Code

- Prefer Claude Code's native tools, project instructions, skills, and hooks when they provide the required behavior.

- Delegate interactive browser automation to the `browser` subagent through the `Agent` tool, as one workflow per site session, and keep answering the user while it runs. Unless the user explicitly instructs the main agent to operate the browser directly, never call `mcp__camofox__*` tools from the main agent, and never drive a browser by another route, such as ad-hoc Playwright, headless Chrome, or scripted HTTP against a logged-in site. Give the subagent the goal, authorized effects, required inputs, credential locations rather than secret values, and observable completion criteria. When handing off a user-supplied one-time code or secret that is not stored in Keychain, 1Password, or `totp`, write it to a mode-`0600` temporary file (`mktemp`) without printing the value and pass only that file path, which the subagent types with `camofox_type(textFile=...)`. When the subagent yields `blocked` or `partial`, or the user sends a follow-up or stop request, relay it to that same subagent with `SendMessage` and its agent ID so it resumes on the same tab; start a new one only for an unrelated workflow, and never run two browser subagents against one login session. When `WebSearch`, `WebFetch`, or an API is blocked (403, bot detection, login wall), retry through the `browser` subagent before concluding the data is unavailable.
